# となり街 / tonari-town

AIパートナーとの日常が、小さな街に並ぶWebアプリ。
三人称視点で街を散歩すると、家からパートナーの言葉が吹き出しで見えます。

## PoCを動かす

Node.js 22.12以降を使用します。

```sh
npm ci
npm run dev
```

`http://127.0.0.1:5201/` を開いてください。ポートが使用中の場合は、別のポートへ自動変更せず停止します。Supabase未設定でも架空の住人がいる街を試せます。
このモードの保存先はブラウザのlocalStorageです。クラウドには保存・公開しません。

1. 地面のタップ、四方向の矢印ボタン、矢印 / WASDキーで街を歩く。川は橋を渡り、住宅街や河川敷、林を散歩する。
2. 台詞のJSONを貼り付けて「台詞を確認する」を押す。
3. プレビューを確認し、街の空き地やマンションの窓をクリック、または場所の選択欄から住まいを選んで保存する。
4. 再読み込みして、自分の家と台詞が残ることを確認する。

戸建て12区画とマンション6室を選べます。選択だけでは入居は確定せず、保存時に確定します。一人につき一軒で、別の場所に保存すると引っ越します。マンションは外観と窓からの台詞表示までで、室内への移動はありません。

「住人の表示設定」で、特定の住人の名前と台詞をこのブラウザだけで非表示にできます。建物と区画の占有状態は残ります。設定はlocalStorageに保存し、サーバーへ送信しません。別端末への同期やXのブロックとの連動はなく、サイトデータの削除で解除されます。Xのフォロー一覧取得は実装しません。

街は小さな固定マップです。クリック移動は目的地へ向かう移動で、障害物を迂回する経路探索はありません。橋や曲がり角では途中の地面を選び直してください。

アクセスすると街の概要を表示します。「散歩する」を押すと、ログインなしで街がブラウザーの表示領域いっぱいに広がります。右下の「?」で歩き方やカメラの操作ガイドを開けます。右上のタスク「住む場所を決める」から家の登録・編集を開けます。Supabase接続時は保存にXログインが必要で、保存ボタンの手前で公開範囲を確認できます。

## 別のPCから開く

LAN経由で開く場合は、開発サーバーを `npm run dev:lan` で起動し、`http://<開発PCのLANアドレス>:5201/` にアクセスします。

VS Code Remote SSHでは「ポート」タブから5201を転送すると、手元のPCの `http://127.0.0.1:5201/` で開けます。Xログインの検証には、この方法を推奨します。ブラウザの認証用暗号機能を利用でき、既存のローカル用Redirect URLも使えます。

## 構成

- React / TypeScript / Three.js / React Three Fiber：画面と3Dの街
- Cloudflare Workers Static Assets：静的ファイル配信
- Supabase Auth：X OAuth 2.0ログイン
- Supabase PostgreSQL：家と台詞の保存、所有者と公開状態によるRLS

共通3D素材はコードで生成するため、PoCでファイルストレージは使いません。
歩行とカメラ追従はReactの再描画から分離し、吹き出しは近接範囲の出入りに応じて更新します。樹木はインスタンス描画し、影は1024px、描画のDPRは最大1.25に制限しています。
ユーザー同士のチャット、移動のリアルタイム同期、アプリ内でのAI生成は範囲外です。

## 検証

```sh
npm run build
npm test
npx playwright install chromium
npm run test:e2e
npx playwright test --config playwright.auth.config.ts
npm run format:check
```

ブラウザテストは接続設定のないお試しモード向けです。ブラウザを取得できない環境では、`PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` に既存のChromium実行ファイルを指定できます。

`playwright.auth.config.ts` は架空のSupabase接続先と認証応答を使い、ログイン状態の復元・期限切れ時の更新・ログアウトを検証します。実際のX認証は行いません。

## ログイン状態について

ログイン状態はSupabase SDKがブラウザに保存・自動更新します。同じブラウザの同じURL（スキーム・ホスト・ポート）を使い、ログアウトせず再訪すれば、保存されたログイン状態を利用します。ローカルURLと公開URL、別のChromeプロファイルでは共有されません。サイトデータの削除やセッションの失効時には再ログインが必要です。

Xでログインし直す際の権限確認と、街のログイン状態の維持は別です。調査内容と実機での確認手順は [PoCの検証記録](docs/poc.md#ログイン状態の維持の確認) を参照してください。

SQLテストはPGlite上で実際のマイグレーションを実行し、匿名・所有者・別ユーザーの権限とデータ制約を検証します。Supabaseの認証部分はテスト用のユーザーと `auth.uid()` で代替しており、XやホストされたSupabaseの接続確認にはなりません。

Cloudflareのローカル配信は、ビルド後に次で確認できます。

```sh
npm run cf:dev
```

## 外部サービスへの接続

利用規約は `/terms`、プライバシーポリシーは `/privacy` です。ログイン付近とフッターのリンクから閲覧でき、CloudflareのSPA fallbackで直接アクセス・再読み込みにも対応します。

運営者は @Enashimaga3、お問い合わせ先は <a href="https://x.com/Enashimaga3" target="_blank" rel="noopener noreferrer">X (https://x.com/Enashimaga3)</a>、施行日は2026年11月22日です。Xの設定にはWebsite URLとして街のURL、Terms of Serviceとして `/terms`、Privacy Policyとして `/privacy` の公開URLを登録します。

アプリはXログイン時に追加スコープを指定しません。実際の要求権限はSupabase/Xの設定・同意画面で確認し、最小限にしてください。街にはXプロフィールではなく登録したパートナー名・台詞を表示しますが、公開データにはSupabaseの所有者IDも含むため完全匿名ではありません。一認証ユーザー一軒の制約はありますが、同一人物の複数Xアカウントを検知する実装はありません。

アカウント作成後の設定方法と、確認済み・未確認の項目は [docs/poc.md](docs/poc.md) に記録しています。

公開用のSupabase URL・Publishable keyだけを `.env.local` に設定します。XのClient SecretはSupabaseの管理画面に設定し、このアプリの環境変数には入れません。
開発ルールは [AGENTS.md](AGENTS.md) を参照してください。
